**Security Defect**
The method suffers from **Insecure Direct Object Reference (IDOR)**. By filtering solely on `jobId` while ignoring the `tenantId` provided in the request, the system fails to enforce **horizontal access control**. An authenticated user from Tenant A can retrieve, modify, or delete resources belonging to Tenant B by simply enumerating valid `jobId` values. This allows cross-tenant data leakage and unauthorized manipulation.

**Required Query Predicate**
The query must enforce both identifiers to ensure the job belongs to the requesting tenant.

**SQL Predicate:**
```sql
WHERE job_id = :jobId AND tenant_id = :tenantId
```

**Words:**
"Select the job record where the job ID matches the requested ID **AND** the tenant ID matches the authenticated user’s tenant ID."

**Test Requirements**
The test suite must prove that the repository method correctly isolates data by tenant. Specifically, it must verify:
1.  **Positive Case:** A user from Tenant A can successfully retrieve their own job.
2.  **Negative Case (Cross-Tenant):** A user from Tenant A attempts to retrieve a job belonging to Tenant B. The system must **reject** this request (returning null, 404, or an authorization error) and **must not** return the job data.
3.  **Isolation:** Confirm that no data from other tenants is exposed, even if the job ID is valid globally.
