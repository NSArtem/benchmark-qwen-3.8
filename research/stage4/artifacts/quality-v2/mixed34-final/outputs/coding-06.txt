**Security Defect:**
The repository method suffers from **Insecure Direct Object Reference (IDOR)** or **Broken Access Control**. By filtering solely on `id`, the system ignores the `tenantId` provided in the request. An attacker can bypass their tenant boundary by guessing or enumerating valid job IDs belonging to other tenants, thereby accessing or modifying data they are not authorized to view.

**Required Query Predicate:**
The query must enforce multi-tenancy by filtering on both identifiers.

*   **In Words:** Select the job where the job ID matches the requested ID **AND** the job’s tenant ID matches the request’s tenant ID.
*   **In SQL:**
    ```sql
    SELECT * FROM jobs 
    WHERE id = :jobId AND tenant_id = :tenantId
    ```

**What the Test Must Prove:**
The test must demonstrate that the implementation correctly isolates data by tenant. Specifically, it must verify that:
1.  **Positive Case:** A request with a valid `tenantId` and a `jobId` belonging to that same tenant returns the job.
2.  **Negative Case:** A request with a valid `tenantId` but a `jobId` belonging to a *different* tenant returns no results (empty set or 404/403 error), proving that cross-tenant access is blocked.
