**Test Name:** `test_stale_event_after_terminal`

**Preconditions:**
1.  Initialize the state machine to `ACTIVE`.
2.  Process a valid transition event `E1` to reach the terminal state `CLOSED`.
3.  Verify the system correctly enters `CLOSED`.

**Event Sequence:**
1.  **Step 1:** Dispatch `E1` (e.g., "Order Completed").
2.  **Step 2:** Assert state is `CLOSED`.
3.  **Step 3:** Dispatch a stale event `E2` (e.g., "Order Shipped") that logically precedes `E1` but arrives after the terminal state.
4.  **Step 4:** Dispatch a stale event `E3` (e.g., "Order Cancelled") that is invalid for the current terminal state.

**Terminal-State Invariant:**
Once the state machine reaches a terminal state (defined as a state with no outgoing transitions), it must remain immutable. No subsequent event, regardless of timestamp, sequence number, or type, may alter the current state or trigger side effects (such as database writes or notifications).

**Assertions:**
1.  **State Integrity:** After processing `E2` and `E3`, the current state must remain `CLOSED`.
2.  **No Side Effects:** Verify that no database updates, API calls, or message queue emissions occurred during the processing of `E2` or `E3`.
3.  **Error Handling:** The system should log a warning for the stale events but must not throw an unhandled exception that crashes the service.
4.  **Idempotency Check:** Re-dispatching `E1` (the original transition) should be a no-op, confirming the terminal state is stable.

**Pass Criteria:**
The test passes only if all assertions in Step 4 hold true, ensuring the terminal state is strictly enforced and never reopened by late-arriving data.
