# Integration Test: Timeout-After-Commit Retry with Idempotency Key

## Test Scenario

Two concurrent `POST /orders` requests share the same idempotency key (`idem-123`). The first request commits successfully, but the client times out before receiving the response. The client retries with the same key. The worker (async job) is artificially delayed. We verify that:
1. Only **one** order row exists in the database (no duplicate).
2. The retry returns the **original** order (not a new one).
