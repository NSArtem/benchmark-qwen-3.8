### Diagnosis of the Incident

The reported symptoms ("completed render returns to running" and "second render created") stem from three distinct but related violations of the system's invariants in the current codebase.

#### 1. Idempotency Race Condition (Creates Duplicate Jobs)
**Invariant Violated:** *Every mutation carrying an idempotency key returns the same result on a retry.*

**Root Cause:**
In `apps/api/src/application/job-service.ts`, the `create` method performs a "check-then-act" pattern within a single transaction:
1. It checks for an existing idempotency record.
2. If not found, it inserts a new job, outbox row, and idempotency row.
3. It commits.

In a high-concurrency scenario (e.g., two replicas of the API), both requests can read "no idempotency record" before either writes.
- **Request A** inserts Job A, Outbox 1, Idempotency Key. Commits.
- **Request B** inserts Job B, Outbox 1, Idempotency Key. Commits.
