`--no-mmproj`:

```sh

  -hf unsloth/Qwen3.8-27B-GGUF:Q3_K_M \

  -c 256 -n 16 -b 128 -ub 128 \
```

## Harness

The reproducible harness is
[qwen38-gguf/harness/run_case.py](harness/run_case.py). It uses standard
Python only and is launched through `uv`:

```sh
UV_CACHE_DIR=/private/tmp/qwen38-gguf-uv-cache \
  uv run --no-project python qwen38-gguf/harness/run_case.py \
  --name NAME --prompt-file qwen38-gguf/prompts/PROMPT.txt \
  --context CONTEXT --output-tokens 128 \
  --batch BATCH --ubatch UBATCH \
  --kv-k KV --kv-v KV --flash-attention auto \
  --fit-target 2048 --load-mode none
```

Correctness gate:

```sh
# 4K: context slot 4608, prompt 4035 tokens
# 8K: context slot 8192, prompt 7903 tokens
# 16K: context slot 16896, prompt 16359 tokens
```

The successful correctness runs used Q8 KV, batch 256, ubatch 128, and
`--load-mode none`. The measured tuning run used Q8 KV, batch 512, ubatch
512, context 16896, and `--load-mode none`.

Context extensions used the winning settings:

```sh
# 24K: --prompt-file qwen38-gguf/prompts/24k.txt --context 25088
# 32K: --prompt-file qwen38-gguf/prompts/32k.txt --context 32768
```

The one Flash Attention OFF comparison failed at context creation because
quantized V cache requires Flash Attention. No FA sweep was performed.

## Winning interactive command

This uses the exact selected model and the practical 16K settings. Omit
`--offline` so llama.cpp can resolve the normal cache/HF source if needed:

```sh
llama-cli \
  -hf unsloth/Qwen3.8-27B-GGUF:UD-IQ3_XXS \
  --no-mmproj --no-repack --load-mode none \
  --fit on --fit-target 2048 \
  -c 16896 -b 512 -ub 512 -fa auto \
  -ctk q8_0 -ctv q8_0 \
  --reasoning off --reasoning-format none \
  --conversation --multiline-input
```

No `--single-turn`, speculative decoding, MTP, mlock, or CPU-only mode is
used in the interactive command.
